# Health Picture saved-report authority

This bounded data layer supports the ADR-0017 comparison of existing reports. It does not compute a child forecast, combined score, carrier result or ROH. Page/projector integration and real-browser acceptance remain separate work.

`loadHealthPictureSnapshot(db, {selfSubjectId, counterparts, purposes})` returns `{state, confirm}`. Each column keeps per-purpose `canonical`, `legacy-only` or `not-shared` access, prepared/completed flags, exact legacy file IDs, safe completed-source provenance, and separately captured report outcomes/catalogs. `authorized` means the supplied comparison snapshot passed current authority; it does not mean every purpose has a result. No prepared source means **No prepared file**, not **No file**. A missing own choice/completion remains empty without suppressing another valid layer. A missing captured catalog is explicitly unavailable; current templates never decorate historical outcomes.

Call `confirm()` after all other awaited page work. Render only its returned state. It resolves the actual viewer/session and jurisdictions before one terminal DB transaction for all columns, purposes, source pages and empty/not-shared captures. Stable NOWAIT locks hold account, endpoint, grant, source, normalization and completion bindings through the final comparison. A final clock fence follows the last authority pass and covers live store and purpose expiry. Any mismatch permanently closes that capture; it never becomes permission to retry through a legacy reader.

A canonical shared column requires both `family.heritability` directions, a separate B-to-A report-layer grant, and B's independently current own store/report/source/completion authority. It does not synthesize B's session. A's own reports use A's actual session and own authority. Each counterpart is checked separately within the same final transaction. Historical joint or report grants remain legacy-only; another independently authorized column remains useful.

The Permissions page adds a signed `healthPictureEndpointReceipt` only for an explicit Health Picture grant. Presentation snapshots current account/subject/principal/binding and directional-relationship revisions. The versioned commit locks and compares that receipt before the original signed grant transaction, then records the actual resulting relationship. Reaffirmation replaces an unproven grant; there is no backfill. Ordinary off/on does not mutate the opposite relationship revision. No new results or raw data are stored, and the new private grant snapshot cascades with its existing grant during account/grant cleanup.

Legacy computation may use only the captured column's `legacyFileIds` with the restrictive readers in `genome/load.ts` and `family/roh.ts`. Those readers repeat exact subject/annotated/null-canonical-marker checks. **A not-shared purpose must not call a legacy computation**, even if another purpose permits the same files. Preserve separate source/catalog identities when constructing rows; incompatible captured template versions are not interchangeable measurements.

Install the additive migration before replacing the application. Existing application grants can continue to use the old RPC and retain legacy-only meaning. A newly deployed application requires the new receipt; a stale pre-deployment Health Picture prompt receives `consent_unavailable` and must be refreshed. Rolling back the application does not turn old grants into canonical authority. No migration, worker, provider or hosted action is enabled by this module.
