# Production report catalog refresh: citation access dates, 28 September 2026

Pull request #247 (G4.7) dated 170 report-template citations whose sources were
retrieved and checked on 28 September. It merged as `1291052f`. Production
serves report text from `public.report_templates`, which a deploy does not
refresh (D-134). This record is the guarded refresh that brought those
citations to `main`, and the checks that it did exactly that.

## Scope

- 129 published rows of `public.report_templates` in project
  `zuvloczwgrayonqabnss`.
- On each row, the only change is `"accessedOn": "2026-09-28"` added to the
  citations #247 dated: 170 citations in all.
- No title, summary, genotype reading, citation source, category, evidence,
  layer, estimate kind or `pgs_id` changed. No schema, no other table.
- The six citations #247 left undated because their sources contradict the
  report, and Markt 2016, are unchanged. They are handled by the corrections
  pull request.

## The statement

[`refresh.sql`](refresh.sql), SHA-256
`81185d2ba48e3f5f690b1a5836b7f9607cd37737a56864717cdd826f4d1627ad`, executed
unchanged. It was generated by [`gen_dating_refresh.py`](gen_dating_refresh.py), which reads
[`catalog_digest_lib.py`](catalog_digest_lib.py), from `data/templates` at
`f40e6174` (the predecessor production held after the CF refresh) and at `main`
`1291052f` (successor).

- The generator refused to run unless, on every changed row, the only
  difference was an added access date on an otherwise identical citation.
- It checked that no existing date changed and that every added date is
  `2026-09-28`.

One `DO` block, so it commits or rolls back as a whole:

1. `lock_timeout` 1 s, `statement_timeout` 15 s, idle-in-transaction 15 s.
2. Locks every published row.
3. **Predecessor guard:** the whole-catalogue digest must equal `data/templates`
   at `f40e6174`: `ba371662d06b340c2778ea6945eb684f`.
   - The digest is one md5 over every published row in byte order of slug.
   - Each row contributes slug, category, evidence, layer, estimate kind and
     `pgs_id`, plus md5s of title, summary, `variants::text` and
     `citations::text`.
4. Adds the access date to each listed citation, by position. It fails unless
   exactly 129 published rows are updated.
5. **Successor check:** the whole-catalogue digest must then equal `main`
   `1291052f`: `e024bd182f979efb6852617f59b8ee9e`. 162 templates must still be
   published.

Because both guards cover every field of all 162 published rows, nothing else
in the catalogue can have changed. [`digests.json`](digests.json) lists each
changed row's citations md5 before and after, and its template file.

## After

- **The whole catalogue equals `main`:** production gives
  `e024bd182f979efb6852617f59b8ee9e` over 162 rows, and so does `data/templates`
  at `1291052f`.
- **Exactly 129 rows changed,** all with one `updated_at`,
  `2026-09-28 10:55:21.709851+00`: one transaction.
- **Saved reports unchanged.** `private.capture_own_report_catalog_v1` keeps
  completed results immutable, so a saved report keeps the citations it
  captured. An access date is not a scientific correction, so no correction
  notice applies.
