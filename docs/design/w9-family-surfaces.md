## 2. Each surface

### 2.1 `/family` (signed in)

Order: the two public panels (only for the signed-out branch; signed in they move below the hub as one "Where this works" line linking to `/legal/where-inherit-works`? — no such route exists; link to `/legal`), h1, the people list, one primary `Action` "Add another adult" → `/family/invite` (`brief:328,234`), the three entry tiles, the not-diagnostic line (`NOT_DIAGNOSTIC`, as `/genome/[subject]` does).

People cards (`brief:328`): 24px disc with initial, name (`FamilyPerson.displayLabel`), kind chip from `KIND_CHIPS` via `subjectKind`, one state line: `"Reports ready"` when the data subject has ≥ 1 annotated file **and** at least one report-layer grant to the viewer is live; `"No file yet"` when no annotated file; `"Sharing paused"` when paused. A fourth line is needed for the commonest state — accepted, file present, nothing granted — because "Reports ready" would then be false: `"Waiting for {name} to share"` (open decision 1). File counts and processing state of another adult are shown only when a report-layer grant is live; without one the card reveals nothing about their files. Nobody is ordered by anything but name.

Tiles: "Individual risks" → the first person with a live report grant (`route("family.person")`) else the blocking state on this page; "Portrait" → `route("family.portrait", { pairId })` when a `family_pairs` row exists for the viewer (pending or current) else the blocking state; "Copilot" → `route("copilot.scope", { scope: "family" })` once `COPILOT_GROUP_SCOPES_AVAILABLE`, else the person-scoped Copilot of the first shared person (`s-{handle}`), else blocked. A blocking state is a card sentence, never a dead link (precedent `decisions.md:125-127`).

## 5. Data and computation

- **From existing tables**: people and grants (`subject_invitations`, `subjects`, `subject_principals`, `purpose_grants ⋈ directional_grants`, `family_pairs`), files and genotypes (`genome_files`, `user_variants` via `getSubjectGenotypesByRsid(admin, dataSubjectId, rsids)` — union of processed files, conflicts render `FILES_DISAGREE`), templates (`getPublishedTemplates`, `isFixtureSlug` filter, `categoryFor`), classifications (`ref_variants.clinvar_significance`, `clinvar_review_status`), inheritance (`condition_registry.inheritance_mode` + requested `gene_symbols`), jurisdiction (`profiles.jurisdiction_code`, `data/jurisdictions.json`).
- **Computed, server, at request time** (A.7 `brief:2215`: "query-time report resolution, carrier arithmetic" are serverless): `src/lib/family/graph.ts`, `access.ts`, `tier2.ts`, `carrier-pair.ts` (candidate set, trigger evaluation, reasons, `countCarrierMatches`), `roh.ts` (per-file F_ROH from autosomal runs of homozygosity; array files only; a VCF that lists only differences is `not_measurable` — the brief's thresholds 100 Mb / 0.0156 `brief:1349` are the only numbers used and are quoted from it; this is a within-one-file quantity, not relatedness between two people, and the ADR states that distinction), `mendel.ts` (the six canonical crosses as exact fractions; AR both het, AD one het, X-linked mother-carrier / father-affected splits over 100 pregnancies; `no outcome renders zero` test, `brief:2238`), `distribution.ts` (categories → dot counts summing to 100 by largest remainder, reusing `apportionShares` from `src/lib/ancestry/present.ts`).
- **Computed by the worker**: `compute_portrait` (`worker_jobs.kind`, `output_kind 'family.portrait'`) writes `portrait_results(kind='carrier_pair')` with `source_binding_fingerprint` over both files' SHA-256 and grant revisions; the page reads results and recomputes only the presentation. Until the worker job exists, the page computes carrier pairs at request time (serverless is permitted for carrier arithmetic) and writes nothing.
- **Never computed** (`brief:348`, acceptance 20, X15): relatedness coefficients, shared-DNA length, IBD segments, kinship, relationship labels; any cross-column difference (`brief:344`); any polygenic estimate for a hypothetical child (`brief:1357`); any personal heritability number (`brief:2476`); any sex prediction (`brief:356`).
- **Purge**: `stop`/revocation targets `portrait_results` (pair), `chat_messages` by `retrieved_subject_ids`, cached comparisons (none persisted), `family_pairs.status` (`docs/retention.md:14,17,20`; `brief:2244`).
