# Fresh participant-c instrument launcher

The separate `Fresh participant-c smoke` manual workflow calls
`scripts/comprehension/run-fresh-t6.mts` in its genuine GitHub-hosted Linux
`fresh-t6` job. It runs the deterministic stub for two personas. It has no paid
credential and is absent from the standard browser workflow and its six native
partitions. The native case set, assertions, retries and timeouts stay intact.

Before creating any stack, the launcher verifies the real GitHub OIDC signature,
issuer/audience, exact repository/manual workflow/source SHA/ref/run/attempt and
hosted-runner claim. The bearer token is never stored or passed to children.
The claim contract follows [GitHub’s OIDC reference](https://docs.github.com/en/actions/reference/security/oidc).
Environment strings alone cannot authorize this separate launcher.

Before the production build, and before each persona, the launcher refuses any
existing Supabase/browser resource. It uses an exclusive private runner lock,
copies the exact clean source migrations/configuration, starts a new `sequence`
stack, compares its complete migration-version ledger, and captures container,
volume creation and network identities. The build bootstrap is disposed before
the first persona. Each persona performs the same actual signed-parent upload,
measured worker and whole-cohort publication journey as the native case. It then
opens its own signed-in read session from Overview. No consent, signature, QC,
source, result or provider acknowledgement is inserted as a substitute.

Each stack maximum is reserved **before** resource creation in the same effort
spend journal used for model calls. A repeated run reserves new maxima. No
hosting invoice is inferred: these reservations stay at their full maxima after
success or failure. Model calls retain the conductor's existing per-attempt
reservation, isolation, retry bounds, blind grader, stopping rule and hard
US$50 effort ceiling. The workflow uses synthetic accounting and the local stub;
its infrastructure ceiling is not a receipt for a paid provider invoice.

Cleanup first closes the read browser, both app processes and synthetic mail
receiver, then removes only the exact owned runtime. The Supabase stop is
allowed only while every captured resource identity matches. The lock releases
only after the inventory is empty. An uncertain start or disposal retains its
receipt and stops the run; there is no reset, prune, cleanup adoption or reuse.
App/container/infrastructure child environments omit inference credentials.

The fresh persona bootstrap gives only its embryo app on 3105 a newly generated
32-byte webhook verifier in process memory, matching the strict server launcher.
The main app on 3100 receives none. This corrects a missing configuration field;
it creates no delivery callback, provider acknowledgement or native result. The
focused configuration regression does not qualify the hosted stack lifecycle.

The private configuration wraps the existing run configuration as `run` and
adds `maximumInfrastructureCostPerStackMicroDollars`. Only explicit standard T6
smoke/calibration is supported. `--plan` reads that configuration without
creating resources or making calls. `--prepare` builds once through its own
fresh bootstrap. Actual execution admits only the existing strict hosted fence
and the separate job; setting CI/GitHub variables on a Mac is unsupported.

Authored lifecycle/refusal tests and native discovery are source checks. The
new workflow has not executed at this checkpoint. Its real two-persona runtime,
complete publication/read/cleanup, build-bootstrap keys and environment need
hosted proof before claiming this T6 orchestration works. T6-only runs are
partial, and a stub is never comprehension evidence. Ordinary comprehension
still retains its T6 hold, and T7 requires its own genuine fresh no-model
read/action proof. Its honest unavailable-state binding requires no new risk
model; this separate launcher still runs only T6. There is no acceptance flip, full-round claim or paid
run here.
