# Keyless documentary lookup prerequisite — 1 October 2026

This implements the prerequisite in brief1799 and the registered
`future-person-claim-resolution-v1.keylessCandidateBranches`. Production
remains closed. It does not close G5.4 or authorize a positive determination.

The assigned reviewer reads and explicitly attests the two complete clean
documents, enters their verified name/DOB, and calls the separately registered
documentary lookup. The current own-JWT/MFA/assignment/document-receipt RPC
searches durable current unbound claimant HMACs first. Zero proceeds to
parent-controlled optional profiles; multiple never falls through or selects.
Only the unique assigned case can reach the decryptor and reviewer. The
intake place/names and stored profile remain candidate signals. The
documentary DOB, rather than parent input, supplies the adult-age check.

The encrypted proof uses the existing external root, a separate purpose and
authenticated encryption. It carries only a receipt digest and original
ten-minute timestamps; its receipt binds the reviewer, own auth session,
assignment, auth revisions, both kind-bound document digests, verified tuple
and current matching snapshot. It has no independent approval authority.
Final decision must repeat the whole lookup and consume its distinct existing
one-use decision nonce atomically. No new durable store, retained documentary
field, owner secret or retention clock is added by this prerequisite.

The read-only lookup's separately purpose-bound page proof is explicitly
registered in the authorized case-session response. It is distinct from the
consumed decision nonce. Read audit uses the existing coded case-read event
and carries no names, DOB, selector, candidate count or outcome.

## Remaining whole-flow work

- Final documentary/profile/recorded-parent attestation and subject-first
  positive transaction, including current uniqueness and all purge/lifecycle
  rechecks. Equality alone cannot approve.
- Atomic `approved_pending_owner_notice` and exact current-owner outbox,
  minimum encrypted package transfer under the registered62-day phase, and
  genuine provider completion before its persisted delivery deadline. A
  queued outbox or elapsed time cannot start the full30-day notice clock.
- Current-owner objection credential and action, exact notice deadline,
  suspension, named-human objection review and terminalization of stale or
  undeliverable attempts.
- Separate fresh named-human release after the complete persisted notice
  period, with fresh full-document review and all current revisions, followed
  by the actual custody/release transaction and exact package shredding.
- Fresh Recovery-Key and prior-unbound no-key restoration with real rotation,
  current durable identity recheck and independently bounded contact working
  material. The current lookup does not open either recovery executor.
- Actual SQL rehearsal and native browser journeys for all unique, twin,
  stale, cross-subject, unread, notice, objection and second-review boundaries.
  Synthetic metadata and an authored proof do not establish execution.

The existing mail worker supplies a concrete provider completion interface:
it authorizes the exact current attempt immediately before submission and
commits successful `complete_mail_attempt` only after an actual provider
message ID is returned. The new notice phase must connect to that existing
exact-attempt contract; it must never synthesize its receipt or reinterpret an
unacknowledged or uncertain send as delivery.
