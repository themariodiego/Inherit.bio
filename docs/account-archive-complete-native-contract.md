## Scope comes before membership

The account archive must enumerate every applicable portable-data class, with
an exact included or excluded disposition, the actual source count, the emitted
count and the authority used. A zero emitted count is not a claim that the
source was empty. A missing projector remains a whole-request refusal; an
explicit privacy exclusion is a complete scoped disposition. The full native
source capture must still bind excluded source state and its current authority,
so neither an empty page nor a digest can adopt a changed source.

The existing subject export remains unchanged. The complete account door must
use its own versioned context and receipt. Its public compatibility subframes
are the exact existing account member context, class inventory and history
inventory for the ordinary and claimed-bound subset. Routed supplements must
have separate count/hash/partition receipts; whole membership must equal legacy
plus routed membership without overlap. The current incomplete account capture
must not run first and refuse an otherwise supported complete account request.

### Raw data and reports are separate

The brief's X11.3 and G5.6 permit the person's own genome and results in full.
For another subject or embryo they permit consent records, file metadata and
only those derived results the consent covers. They expressly exclude another
subject's raw variant rows unless that subject separately grants raw export.
See `docs/inherit-v2-brief.md:2526` and `:2679`.

`variants` is a descriptive signed `subject_consents.scope` value, not a
`purpose_grants.purpose`. It is not analysis permission. A foreign ordinary raw
source requires the actual current subject/signing account, the current subject
and recipient bindings, the current directional relationship, separate live
`raw.export` and `export.share-link` grants, their exact signed current artifact
and jurisdiction/binding revisions, and the existing other-adult hold/refusal.
Neither a file-owner match nor `resource_authorized_v1`'s owner shortcut supplies
this tuple. Source custody is checked against the real stored owner only after
the distinct reader authority succeeds; no owner session is borrowed.

The current own-storage signer writes only the `store` signature and
`upload_class` scope `['store']`; it does not issue a new `self_source` variants
consent (`20260906102710_own_upload_consent.sql:128–147`). The historic backfill
of signed self-source scopes is not a callable present-day issuer. Two genuine
directional purpose grants therefore still cannot export a foreign self raw
source without that separate live scope. The authored negative preserves this
real refusal rather than installing a new issuer or consent text.

A genuine existing positive is Path A: the mailed invitation's actual rights
session acceptance signs `consent.subject-adult` v1, binds the accepting account
with `adult_claim`, writes signed `adult_source` variants scope, and removes the
Path A draft (`20260928150000_other_adult_held_upload.sql:2032–2088`). The new
internal export gate checks that exact accepted invitation, active principal
and binding, current account/jurisdiction, current artifact body, five statement
keys and signature revisions. It then retains all independent recipient,
relationship, `raw.export`, `export.share-link`, source and expiry gates. Every
Path B/uploader source still uses the unchanged Path B mitigation helper.
Missing, withdrawn, stale, mismatched and unrelated Path A evidence refuses;
the subject class or an owner's Boolean is never the proof.

The existing cohort upload artifact is version 1 of `consent.upload-embryo`,
body SHA256
`8868f876f71e320f64983e5dbae2757f0092462eb2baacfd0eb3ce8baae37971`.
Statements 8–10 authorize one purpose only, analysis of these embryos on Inherit,
and say this switches nothing else on. `grant_cohort_purpose_v1` issues only
`embryo.analysis`, with direction `self` to the signing contributor's own
account. The current producer validates that precise tuple for every required
principal. See `content/legal/consent.upload-embryo/v1.md`,
`supabase/migrations/20260905103317_embryo_cohort_runtime.sql:3001` and
`supabase/migrations/20261002132000_embryo_observed_carrier_producer.sql:133`.

That tuple does not authorize parent raw rows or a new recipient/export action.
The complete account context must declare the six parent science classes
individually: `embryos`, `embryo_qc`, `embryo_scores`, `embryo_figures`,
`embryo_variants` and `report_artifacts`. Current signed analysis is not renamed
to raw export. For raw rows the closed reason is
`separate-raw-export-authority-required`. For a derived result whose actual
recipient/export action is not covered the closed reason is
`export-recipient-consent-required`. The requester's own minimized agreement and
file metadata can be included independently. Claimed-bound subject rights keep
their existing independent custody/claim authority and are not vetoed by a
parent's later analysis withdrawal.

`docs/export-member-plan.json` records these sources as deferred projections;
that classification is not a consent grant. The existing member-selection
design explicitly requires independent raw grants and joint-contributor
projection separately (`docs/export-member-selection-design.md:60`).

## Missing cohort raw issuance: separate closed proposal

This section specifies a review boundary, not an installed door, an approved
consent artifact or new legal text. No existing signature or grant is migrated
into this permission. No default grant, operator allow flag or API-selected
source may enable it.

Before implementation, a reviewed consent artifact must separately describe
the exact cohort/embryo source, canonical calls and any retained original, the
one named recipient, durable downloaded-copy consequences and withdrawal's
prospective effect. It must distinguish raw export from on-site analysis and
from report-only export. The artifact key, statement keys, version and whole
body digest remain unassigned until that text is reviewed.

The issuance contract must:

- Resolve the complete current set of contributors/decision-makers from the
  existing finalized legal basis and participant-set revision. A caller cannot
  provide a subset or consent for a donor. The existing ingest, parentage,
  donor, disposition and Future Person limitations remain.
- Require a genuine authenticated signing account/session for each required
  signer, exact current binding and jurisdiction, the reviewed current artifact
  body and an operation-specific single-use nonce. It must not reuse the
  analysis nonce or an uploader's signature for someone else.
- Bind each separate purpose to the exact cohort, participant-set revision,
  publication/source revision, one actual recipient account and principal, and
  a finite expiry. `raw.export` and `export.share-link` must not be silently
  bundled into an analysis signature.
- Record distinct signatures and grants, with recipient direction and current
  relationship/recipient binding. Reject duplicates, stale participants,
  missing signatures, inactive accounts, revoked/expired grants, changed
  publication, blocked jurisdiction and withdrawn/claimed/erasing embryos.
- Open export only after every required live signed tuple exists. Capture and
  every metadata/canonical/original read must revalidate that complete set and
  source under the existing lock order, before and after bounded reads.
- Preserve Future Person independent claim/rights priority, sex-chromosome
  exclusions, original-source retirement and the full canonical part/EOF/hash
  checks. Raw consent does not create a retained original or undo retirement.
- Have meaningful full-positive native tests through genuine issuance, plus
  wrong recipient, missing contributor, stale/revoked/expired consent, changed
  source, incorrect custody and concurrent withdrawal refusals.

Report-only export needs the same explicit actual recipient/export-action
check, with its reviewed scope kept separate from raw data. This is an
implementation gap under the existing rule, not a reason to broaden analysis
or ask the owner to waive the brief.

## Complete native ABI and source framing

The new service RPC is
`export_archive_account_complete_v1(operation, exportId, attemptId,
authorityReceipt, kind, selector)`. Every operation consumes the same actual
account attempt, originating actor/session, deadline and whole authority
receipt. Native capture is recomputed before and after every bounded read. The
existing request capture/create door selects this complete frame only when the
actual owner-configured R2 row is enabled and the current account is declared
TEST. Configuration must precede the fresh request; enabling it cannot adopt a
previous legacy request. The subject export and default-OFF account delegate
retain their original bodies and ABI.

`account-complete-members-v1` carries exhaustive ordinary, claimed-bound and
consent-covered partitions, exact file IDs, the three strictly versioned public
legacy subframes, `account-complete-capture-receipt-v1`, and complete scoped
dispositions. The receipt has all 29 class inventories, all nine history
inventories, every one of the twelve subject members for every consent-covered
partition, and separate descriptors for every independently raw-authorized
foreign file. It never exposes the internal source/signature capture as a
legacy frame. Account-level metadata retains its original NULL attribution.

Each class declares its unchanged legacy source receipt and a separately
counted/hash-chained routed supplement. An original `excluded` legacy mode
counts withheld sources; its emitted contribution remains zero. Whole emitted
counts and partitions sum permitted legacy plus routed data. Whole hashes bind
both original source census and the routed receipt, while explicit dispositions
retain actual `sourceRows`, `exportRows`, reason and authority digest. A nonempty
held portrait, parent science or raw class cannot look like an empty source.

Routed keys are canonical JSONB `[subjectId, identity]` (file keys are
`[fileId, identity]`) sorted by the entire native `key::text COLLATE "C"`.
Membership chains consume every row in that order using UTF-8
`identity:subjectId:rowText\n`. Each family uses its own declared seed:
`account-complete-routed-v1|kind`,
`account-complete-member-v1|subjectId|member`,
`account-complete-history-routed-v1|kind`, or
`account-complete-file-v1|fileId|kind`. The whole class/history receipt separately
binds the unchanged legacy count/hash and routed count/hash.

`rows`, `member-rows`, `history-rows` and `file-rows` return
`account-complete-page-v1` with complete count/hash framing and ordered EOF. A
page has at most 500 rows and 4,000,000 serialized UTF-8 metadata bytes. Large
supported source rows use the separate `*-bytes` operations and
`account-complete-row-bytes-v1`: exact offset, whole byte count/SHA256, canonical
base64 chunks of at most 786,432 bytes, and complete EOF. There is no new maximum
scientific row size and no omission to fit the metadata bound.

A database file descriptor contains exact physical/revision/raw/decoded
identity and separate variants, observed and canonical receipts. Variants are
the original six-field JSONB scalar object; the archive retains the required
CSV form. Database normalization has an explicit empty prepared-canonical
receipt, not a fictional retired prepared source. Prepared files instead carry
the entire existing `own-prepared-source-v1` receipt; the same full canonical
manifest/member streaming checks remain, under distinct complete raw authority.
`prepared-member` uses a NULL kind and exact
`{fileId, manifestId, artifactId, expected}` selector. `original` likewise uses a
NULL kind and `{fileId, expected}` and returns the separately versioned complete
original envelope. Neither door borrows an uploader's own-reader session.

## Owner-only TEST delivery draft

The existing R2 allocation/current-object protocol and permanent all-writer
fence remain. Provider reads do not advance a download. The new owner-only
delivery context resolves the actual stored account download, cookie, origin,
current authority and immutable 15-field READY result. The new READY door
independently requires the exact native complete-enabled TEST origin before and
after whole source recapture. An application flag alone cannot open it. SQL
NULL means only that
the session belongs to a different download family; wrong authority on an
existing account session raises fixed `42501`.

An issued chunk records exactly one ordinal, challenge hash, whole SHA256 and
byte count after complete same-version provider EOF and the current native
segment check. Only an exact browser receipt, after digest verification and
sink write, consumes it and advances `next_sequence`. Duplicate issuance,
duplicate ACK, wrong cookie/origin/ordinal/hash/size, source change and expired
authority refuse. The HTTP layer separately verifies the account-specific
CSRF/HMAC tuple before passing native hashes. It never persists a bearer receipt.

Physical disposal uses a distinct owner-only ACK with exact native allocation
and reservation equality. Evidence must declare terminal all-writer fencing
and actual current-object absence. The old permanent-empty-marker ACK is not
renamed to absence. The native row can validate the exact trusted-owner
evidence and allocation; actual provider deletion/absence must be established
by the original qualified provider operation while the native locks remain.
Uncertain reservations are retained and cleanup remains due. No active-before-
expiry allocation is made disposable merely because a client polled or read.

All metadata and transport limits remain. Large supported scientific rows
need exact byte/source pagination, not omission to fit the metadata bound.
The new migration adds six receipt-state columns only to the existing private
download row; it introduces no new table or export/deletion inventory class.
Its compatibility refinements first require the exact original routine body
MD5 and unique declared source fragment. Unknown predecessors refuse rather
than executing a partial replacement. All current signed texts, registry
activation and legal/clinical defaults remain unchanged.

The authored native controls use genuine storage signing, normalization,
report completion, Path A mail/session acceptance, directional grant issuance,
and claimed-bound custody/release/relocation. They include nonempty retained
science, the twelve related members, exact class/history receipts and a
supported greater-than-4MB source reconstructed through byte pages. The
existing completion protocol adds READY, issue, exact receipt ACK and
independent mismatch/replay negatives inside rollback; its original download
row and every original legacy assertion are retained. Its owner callback
metadata is synthetic and does not prove provider bytes, browser receipt,
physical R2 absence or a complete ZIP. All added native, application, browser
and provider execution remains UNRUN at this source checkpoint. The separate
all-contributor issuance proposal above stays closed.
