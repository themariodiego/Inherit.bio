# Consumed account partition and byte planning

The actual metadata partition projector consumes every row from the nine closed
history inventories, ten supported class projections, actual profile and
selected purpose grants. Every record appears in exactly one authorized subject
directory. Recorded subject targets map to that selected subject. Account-only
history and the requester's genuine actions about an unrecorded or foreign target
map to the actual self partition with `requester-account-history` scope. That
scope preserves the approved actor-only history; it never identifies a historical
audit target or establishes access to the foreign person's source. A missing or
ambiguous actual self, missing subject, changed source, count/hash drift,
revocation or cancellation refuses the projection.

Metadata members use `subject-partitioned-archive-v1`, with tagged
`{kind, scope, row}` entries. Subjects, demographics, own principals/bindings,
profile, relationships and refusal history go in `subject.json`; signatures,
account/provider consent, purpose and directional grants in `consents.json`;
legacy consent in `legacy-consents.json`; affirmations and contradiction history
in `attestations.json`; suppression history in `reports.json`; sharing pause/stop
history in `portrait.json`; claim/principal/objection history in `embryos.json`.
These are requester history sections, not manufactured scientific results.
Existing claimed-bound scientific/agreement/audit factories must remain intact
when the final composer includes these metadata sections.

Preparation retains partition counts, not all history rows. Each member rereads
the complete relevant inventories to EOF and rechecks the actual consumed
authority and original source receipts. The durable check retains its 30-second
operation bound. Empty arrays require real source-absence proof; the projector
does not substitute an empty member for an unsupported recorded class.

The separate byte planner requires all twelve registered A.11 members for every
selected subject and the actual actor ledger exactly once. It generates the
seven other top-level indexes as closed `{subjectId, path}` pointers. A caller
cannot supply sensitive root result rows, omit a required directory, duplicate
a member, add a foreign file or use an arbitrary provider path. Every selected
file has an exact safe descriptor. Live ordinary originals require one complete
byte-identical member and its independent captured raw SHA-256. A genuinely
retired prepared original requires its complete canonical record member instead
of a fabricated legacy expiration. Sanitized embryo files require their complete
logical call source, variants and every exact current immutable canonical part,
including independent identity, sequence, byte count and SHA-256 equality.

All members are consumed to complete EOF before a plan returns. Only names,
counts, byte sizes and SHA-256 descriptors remain; ZIP open rereads the actual
factories and current sources and verifies the same full byte identity at EOF.
Current authority surrounds each operation. Reads and checks keep separate
30-second bounds, original job deadline and cancellation; no source lease is
extended. The manifest lists every payload artifact and its actual partition,
file, row count, length and digest. Its own bytes are covered by the whole ZIP's
existing checksum/completion protocol, as in the existing complete claimant ZIP.
Provider locators, versions, sessions and credentials never enter the manifest.

Focused tests independently compare every projected source class and all 1,103
paged history rows, open all 33 generated artifacts, verify every payload count,
length and hash, and require the independently registered twelve-member set.
They also exercise real signing, copy, old-object disposal and current-part
read/EOF code against the explicit synthetic R2 gateway, with the existing exact
RPC authority seams. Missing, foreign, duplicated, changed, truncated, partial,
revoked and cancelled inputs remain refusals. These unit proofs establish no
real Auth/database transaction, hosted browser or live provider delivery.

This checkpoint is a necessary assembly prerequisite, not the finished whole
account executor. It changes no SQL, persistent store, grant or public/READY
gate. Complete ordinary scientific/prepared/chat factory composition,
claimed-bound metadata combination, every non-self/cohort/joint producer and
actual POST/status worker orchestration remain required. The thirteen currently
unproved nonempty classes retain whole-request refusal. Final provider delivery
and uncertain-write disposition also remain held; G5.6 receives no completion
or acceptance credit from this checkpoint.
